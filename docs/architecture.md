# 架构与存储

Master 在一个进程内维护插件注册表，每个实例有独立生命周期互斥锁；插件由 `go-plugin.Client` 创建为子进程。通用业务只经过 `PluginService.SendMessage`，Master 不判断 Timestamp 或 Heartbeat 的消息类型。

JSON 存储在进程内用单锁串行读改写：写入同目录临时文件、`fsync`、关闭后 `rename`。文件不存在会初始化为 `[]`，损坏文件会让启动失败而不是清空历史。每类历史最多保留 10000 条。

限制：不同 JSON 文件之间没有事务；崩溃可能形成“状态已发生但某条审计尚未写入”的跨文件差异；每次追加会重写整个数组，数据量大时写放大明显；目录本身没有额外 `fsync`，极端断电语义取决于文件系统。当前版本采用单 Master 部署模型，不支持多个 Master 共同写入。

Master 重启后保留注册与历史，但将 runtime PID 清零并视为 STOPPED，不尝试重附着。正常退出会清理它创建的子进程；SIGKILL 无法执行清理。go-plugin 的客户端/子进程通信在宿主消失后通常会终止，但 V1 不把它当作可证明的孤儿扫描机制。
